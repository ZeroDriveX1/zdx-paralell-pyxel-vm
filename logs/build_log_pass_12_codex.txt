  ## Deployment topology tested

  - Physical machines: 1
  - Virtual machines: 0
  - Platform: ARM64 Android/Termux
  - Coordinator: 1 process
  - Workers: 3 isolated spawned OS processes
  - Transport: loopback TCP with mutual TLS and
    Ed25519 application authentication

  This proves isolated-process behavior over
  actual sockets, but not physical or virtual
  multi-machine deployment.

  ## Remaining limitations

  RC2 acceptance is not complete because the
  following were unavailable:

  - Multiple physical or virtual machines
  - Automatic network discovery
  - Actual distributed workload execution/
    redistribution

  - 24-hour soak
  - Privileged latency/loss/jitter/clock-skew
    injection

  - Physical or hypervisor power removal
  - Capacity testing to an observed failure/SLO
    boundary

  - Docker runtime validation
  - systemd validation
  - Windows service validation
  - Automated certificate enrollment or fleet-wide
    rotation

  - Coordinator failover and connection-level DoS
    controls

  The implementation is a substantially hardened
  RC2 candidate, but it should not be promoted as
  fully production-validated until the external
  acceptance run documented in DEPLOYMENT.md is
  completed.
